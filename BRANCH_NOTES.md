# Branch Notes

Single-branch policy: all work happens directly on `main` (operator
instruction). Earlier feature branches were merged and deleted; see git
history for their per-branch audit logs.

## Frontend core port (from Naab)

Brought Naab's core frontend infrastructure into `fe/`, adapted to Diwan
(Arabic-first, RTL, no clinic features), and wired it through `main.tsx` and
the `_app`/`_auth` route boundaries:

- Bootstrap: `main.tsx` now mounts `RootProviders` + TanStack Router
  (`routeTree.gen.ts` is generated by the router Vite plugin and committed).
- Providers: `components/core/root-providers.tsx` — Convex Auth provider,
  TanStack Query client bridged to Convex (`lib/convex/client.ts`), global
  toaster, root error boundary, online-status sync.
- Routing: `routes/__root.tsx`, `routes/_app.tsx` (auth boundary + app
  shell), `routes/_app.index.tsx` (dashboard placeholder), `routes/_auth.tsx`
  and `routes/_auth/sign-in.tsx` (Convex Auth password sign-in; the Diwan
  backend is password-only, staff-provisioned accounts per PRD §5.6).
- Core components: app shell (`layout.tsx` — skip link, header, sign-out,
  font-size selector, offline indicator), error fallbacks, not-found.
- UI kit: button, card, input, label, separator, skeleton, sonner toaster,
  loading spinner — semantic tokens only, RTL-safe logical classes.
- Hooks: `useDocumentTitle`, `useOnlineStatusSync`/`useIsOnline`.
- Stores (zustand): `connection`, `user-preferences` (font scale, kept in
  sync with the `diwan:font-size` boot-script key).
- Config/lib: `config/env.ts` (requires `VITE_CONVEX_URL`), `lib/errors.ts`
  (AppError-code → Arabic message mapping), `lib/utils.ts` (`cn`).

Deliberately not ported yet (needs first real consumers or backend support):
permission hooks/gates (no `me`/permissions query on the backend yet), full
forms field extras (haptics / max-length), data-table completion, PWA.
Feature/clinic dialogs from Naab stay out of scope.

## Sidebar port (from Naab)

Ported Naab's application sidebar, adapted to Diwan's domain and gates
(code-only task per coordinator; verified through the check/build/test gates,
no browser testing requested):

- `components/pages/_app/side-bar/` — desktop rail with `width` transition
  (open ↔ icon rail), label/chevron opacity transitions, active-route
  highlighting, collapsible groups animated with the CSS
  `grid-template-rows` technique from Naab, and a mobile off-canvas drawer
  (slide + backdrop fade, closes on navigation). Collapsed-rail group click
  re-opens the sidebar and expands the group, like Naab.
- `constants/core/navigation-links.ts` — typed nav config
  (`FileRouteTypes['fullPaths']`): dashboard, cases, parties, documents,
  billing group (payments / checks / installments), settings.
- New placeholder routes `/cases`, `/parties`, `/documents`, `/payments`,
  `/checks`, `/installments`, `/settings` (thin file routes +
  `PlaceholderPage`) so every sidebar link is a real typed route.
- Supporting infra: `useSidebar` (persisted open state, tablet auto-rail),
  `useBreakpoint` (matchMedia, synced to theme breakpoints),
  `stores/sidebar-nav.ts` (expanded groups + mobile drawer state),
  `utils/core/pathname.ts` (`isRoutePathActive`), sidebar strings in
  `app-text.ts`, and `AppLayout` now composes the sidebar + a mobile
  hamburger.
- No new dependencies: transitions are pure CSS (no `motion`), drawer is
  hand-rolled (no `vaul`). Tooltips on the collapsed rail, hotkeys, and
  edge-swipe were intentionally left out until their infra exists.

## Sidebar fidelity pass (match Naab exactly)

After coordinator feedback that the first port was not faithful enough:

- Icons are now `weight="duotone"` (parent `size-5`, nested `size-4`),
  matching Naab's `DEFAULT_ICON_PROPS`.
- Header is a copy of Naab's `SideBarHeader`: the whole header toggles the
  sidebar, a `size-10 rounded-2xl bg-secondary` logo square (duotone scales
  icon standing in for the Naab logo) crossfades to the « expand caret when
  collapsed, with a passive » collapse caret at the trailing edge
  (RTL-fixed icon pair; `shrink-0`/`min-w-0` keep the square rigid in the
  44px rail).
- Rows use Naab's exact recipe: `h-10`, 11px inline inset (inline style —
  the checker bans arbitrary `px-[11px]`), `rounded-lg`, ghost/secondary
  variant classes on Diwan tokens, labels `text-sm font-medium` with 300ms
  opacity fade; nested rows are 34px with `ms-2/ms-0` label margin shift.
- Nested list is Naab's grid-rows structure incl. the start-edge guide line
  (`w-px`, shadow, 300ms opacity) and animated gutter margins (14px/0).
- Collapsed rail now expands groups inline (icons only) exactly like Naab —
  the earlier auto-reopen behavior was removed.
- Rail widths `w-70`/`w-17` and `pt-3 px-3 pb-3` gutter, `gap-y-2` nav with
  `mt-1.5 desktop:mt-4`, all as in Naab. Naab's rail tooltips, global
  search trigger (needs a command palette), pointer-down fast navigation,
  haptics, and hotkeys remain out of scope until their infra exists.
